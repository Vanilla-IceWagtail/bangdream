## 一、这个项目解决什么问题

| 想做的事 | 现成方案的坑 | 本项目的做法 |
| --- | --- | --- |
| 用**自己喜欢的角色**玩合成大西瓜 | 原版只有水果；网上改版要么得自己配图、要么图是糊的 | 45 只 BanG Dream! 毛绒娃娃**内置**在图库里（9 支乐队 × 5 位角色），游戏里点「🖼 选图」挑 11 只放到 11 个位子上，**不需要导入任何图片** |
| **分数要能全世界一起比** | 要么自己买服务器/写后端，要么只能本机记分 | 整张榜就是**一份 JSON 文档**，放在第三方免费 KV 上（打开即全球同一张榜）；也支持自建服务器 |
| **手感要"弹"**，不能像石头 | 常规做法是把水果当刚体圆球，撞上去很硬 | 碰撞体按**娃娃轮廓**拟合（不是球），再加**回弹阈值 + 挤压形变**做出果冻感 |
| 素材本身很脏 | 45 张原图里 **40 张扩展名是 `.PNG` 但实际是 JPEG**（没有透明通道）、纯白底、单张 2300×2900 / 1~4MB | 一条工具链把它们变成能直接用的游戏素材（抠白底、裁紧、缩到 384px、拟合碰撞圆、生成缩略图与图库清单） |
| 手机上玩 | 面板一屏放不下、要一直上下滑 | 手机端专门排过版：得分在棋盘上方、即将投放在棋盘右上角，**一屏内看全** |

## 二、主要功能

**玩法与计分**

- 11 级娃娃，长边 = 该级直径（⌀40 → ⌀250），两只同级撞在一起合成上一级：

  | 级 | 娃娃 | 直径 | 合成得分 |
  | --- | --- | --- | --- |
  | 1 | 山吹沙绫 | ⌀40 | 掉落（不计分） |
  | 2 | 上原绯玛丽 | ⌀48 | +1 |
  | 3 | 丸山彩 | ⌀58 | +3 |
  | 4 | 今井莉莎 | ⌀70 | +6 |
  | 5 | 北泽育美 | ⌀84 | +10 |
  | 6 | 千早爱音 | ⌀100 | +15 |
  | 7 | 三角初音 | ⌀120 | +21 |
  | 8 | 三角初音 | ⌀144 | +28 |
  | 9 | 仲町阿拉蕾 | ⌀174 | +36 |
  | 10 | 若叶睦 | ⌀208 | +45 |
  | 11 | 户山香澄 | ⌀250 | +55 |

- **最大玩偶奖励**：两只户山香澄相撞 → 双双消失，额外 +100。
- **连击**：1 秒内连续合成算连击，倍率 `1+(连击-1)×0.3`、封顶 ×2.5；加成取「倍率加成」和「每连击 +1 分」里更大的那个。
- **难度 1~10 级**（默认 Lv.5 熟练）：越难危险线越低、投放越快、越容易掉大娃娃；难度写进成绩，不同难度同一张榜可比。
- **判负**：娃娃堆过红色危险线并静止 2 秒。

**手感**

- **按轮廓碰撞**：每只娃娃的轮廓拟合成一组圆（7~18 个，平均 12.9 个，覆盖轮廓 87%~96%），Matter.js 用**复合刚体**（`Body.create({parts})`）——不是"一个包住它的大球"。
- **果冻手感**两层：① 物理层弹性 0.42 + **低速接触不弹**阈值（堆子静止不微弹）；② 渲染层挤压形变（沿撞击法线压扁、垂直拉长），用**二阶弹簧-阻尼**过冲回摆，晃 1~2 下停住。
- **合成弹出**：新娃娃出生时弹一下再缩回。

**界面**

- **选图小窗口**：左边 11 个位子（角色名 + ⌀ 尺寸 + 颜色条），右边 9 个乐队分组；点图 → 点位子 / 拖拽 / 双击自动填空位；「恢复默认」；没选满 11 位关窗口会提醒。
- **记分板 / 难度 / 即将投放 / 棉花娃娃进化表 / 排行榜**（实时榜最近 20 次 + 总榜前 100）。
- **本局结束先确认名字再上榜**：结算画面填名字（默认「玩家」）→ 点「确认并上榜」才同步，并显示名次。
- **🍮 请作者吃小布丁**：结算画面可打开收款码弹窗。
- **手机端**：一屏内 顶栏 → 本局得分 → 棋盘（右上角浮动「即将投放：」）→ 娃娃堆；按住屏幕拖动瞄准 → 松手投放，连点不会触发双击放大。
- **音效**：WebAudio 现场合成 + 可选真实语音文件（见下面「语音档位」与「音频」）。

**语音档位（右上角按钮，点一下换一档）**

`🎵 全语音` → `✨ 名场面` → `🔇 静音` → 循环，选择会记住（`prefs.voice`）。

| 档位 | 释放玩偶 | 合成玩偶 | 其它 |
| --- | --- | --- | --- |
| **全语音** | 放「当前要投的那一只」的语音 | 放「合成出来的那一只」的语音 | 危险线 / 本局结束照常出声 |
| **名场面** | 不出声（保持安静） | 只有**合成出 9 级及以上**、或**连击 ≥3** 时才出声，而且放的是「名场面」那批台词 | 本局结束放一句名场面 |
| **静音** | 完全不发声（语音与音效都没有） | 同左 | 同左 |

语音取自桌面「全音频」角色台词库（21.6 万个 mp3）：`node tools/import-voice.cjs` 按规则给每个角色挑几句，
复制成 `drop-<级>-1/2`、`merge-<级>-1/2`、`scene-<级>.mp3` —— 目前 **7 只玩偶共 33 条、约 1 MB**。
音源里缺的角色（三角初音、仲町阿拉蕾、若叶睦）自动退回合成音。
挑中的台词见 `assets/voice/台词清单.md`，**想换哪句直接替换同名文件**即可（换完重新跑一次即可生效）。
**临时试听页**：`voice-preview.html`（由 `node tools/make-voice-preview.cjs` 生成，和正式页只差一行 `SUIKA_AUDIO_BASE`）。

**音频（零文件也能玩）**

- 所有音效都用 WebAudio **现场合成**（振荡器 + 包络），仓库里没有任何 `.mp3/.ogg/.wav` ——
  不占体积、不用等加载、也不存在格式兼容问题。
- 已有的音：投放（短三角波）、合成（音高随**玩偶等级**和**连击**升高，连击 ≥3 再叠一层泛音）、
  危险线报警、本局结束（三音下行）。
- **自带限流器**（`js/config.js` 的 `createAudioLimiter`，参数见 `AUDIO_LIMITS`）：
  同时最多 **8 个声部**、任意两声至少隔 **18ms**、同一个音至少隔 **45ms** ——
  连击连爆、警报叠加时不会爆音/掉音（手机能同时混音的声部本来就只有 8~16 个）。
- 切后台会把 `AudioContext` **挂起**、切回来恢复：省电，也避免积压音效一起炸响。

**想加音频文件？浏览器层面没有「文件个数」上限，真正的约束是这几条**

| 约束 | 实际情况 | 对本作的含义 |
| --- | --- | --- |
| 自动播放策略 | 必须由用户手势触发，否则全部静音 | 已处理（首次点击/触摸时 `sfx.unlock()` 解锁） |
| 解码后内存 | WebAudio 解码成 Float32 常驻内存：44.1kHz 立体声约 **353 KB/秒**（≈21 MB/分钟） | 音效要**短**（0.1~0.6 秒）。20 个 0.4 秒的约 **3 MB**，随便加 |
| 同时发声数 | 手机混音器实际 8~16 个；iOS 老版本用 `<audio>` 元素只有 4~6 个 | 已限 8 个声部 + 节流；用 WebAudio 而不是 `<audio>` 标签 |
| 启动解码开销 | 开机一次性 `decodeAudioData` 二十几个文件会卡顿 + 内存尖峰 | 建议按需懒解码（现在是合成，零开销） |
| 托管体积 | GitHub 单文件 >100MB 直接拒收、>50MB 警告；仓库建议 <1GB | 全部音效建议 ≤ **600KB~1MB**（64~96kbps），移动流量也友好 |
| 格式兼容 | 没有一种格式通吃：Opus/WebM 与 AAC/M4A 各缺一边；MP3 到处能放但更大 | 出**两套**（`.opus` + `.m4a`），或只用 MP3 |
| iOS 静音键 | iPhone 按静音键时 WebAudio 会被静音（Safari 16.4+ 可用 `navigator.audioSession.type='playback'` 绕过） | 有人反馈「没声音」时先问这个 |
| 建议规模 | —— | 投放 1~2 + 合成 **11（每级一个）** + 连击 2~3 + UI 3~4 ≈ **20~25 个**、约 8~12 秒音频，毫无压力 |

**工程**

- 无框架、无构建、无 npm 依赖（物理引擎 Matter.js 已内嵌 `vendor/matter.min.js`）。
- **114 项测试**（`node --test`），含整页无头冒烟。
- 调试/自检用 URL 参数：`?shapes=1`（画碰撞体）、`?squash=`（摆挤压形变）、`?demo=1`（自动开局，不动存档）等，见第五节。

## 三、安装方法

**环境要求**

| 用途 | 需要什么 |
| --- | --- |
| 直接玩游戏 | 现代浏览器（Chrome / Edge / Firefox / Safari 均可）。**不需要装任何东西** |
| 用 `.cmd` 起本地服务（推荐） | Node.js（本机已装 v24，仅用内置模块，无需 `npm install`） |
| 自建共享排行榜 | 同上（`server.cjs` 只用 Node 内置模块） |
| 重新处理素材 / 重新生成图库 | Node.js 18+；图片转 PNG 需要 Windows PowerShell（用系统自带 System.Drawing） |

**方式 A：直接开（最省事）**

```powershell
# 双击 index.html，或者：
start "" index.html   # 在项目根目录下执行
```

> 注意：Chrome/Edge 在 `file://` 下**不允许网页存本地数据**，排行榜昵称、你的选图可能记不住（页面顶部会提示）。

**方式 B：本机服务（推荐）**

```powershell
# 双击 启动游戏.cmd，等价于：
node server.cjs            # 默认 http://127.0.0.1:5173/（被占用会自动往后试，最多 +20）
node server.cjs --port 8080
```

**方式 C：静态托管（发给别人玩）**

把整个目录（`index.html` / `css/` / `js/` / `vendor/` / `assets/dolls/`）原样丢到任意静态托管即可，
GitHub Pages 现成例子：`bangdream` 仓库 → 线上 https://vanilla-icewagtail.github.io/bangdream/

**方式 D：自建共享排行榜（可选）**

```powershell
# 双击 启动共享榜.cmd，等价于：
node server.cjs --lan                    # 监听 0.0.0.0，同 Wi-Fi 的人访问你的地址，成绩进同一张榜
node server.cjs --lan --port 5180
```

然后把 `js/config.js` 里 `BOARD_SYNC.provider` 改成 `'rest'`（或临时用 `?board=rest`），
默认走第三方 KV，**不需要服务器**。

**方式 E：从零重建玩偶素材（可选）**

```powershell
# 1) 45 张原图 → 真 PNG（顺带降到 1024px）
powershell -File tools\bangdream\convert.ps1 -Src <原图目录> -Out assets\library-bangdream\src
# 2) 抠白底 / 拟合碰撞圆 / 出缩略图 / 生成图库清单 js/assets-builtin.js
node tools\bangdream\build-library.cjs assets\library-bangdream\src .
# 3) 想看某一张的处理效果（原图 / 抠图 / 碰撞体对照图）
node tools\bangdream\poc.cjs assets\library-bangdream\src\Roselia\凑友希那.PNG 验证.png
```

## 四、使用方法

**操作**

| 操作 | 效果 |
| --- | --- |
| 鼠标移动（不按） | 瞄准（水平位置），跟手 |
| **手机：手指按住并左右拖动** | 瞄准 —— **按住期间不会投放**，可以慢慢找位置 |
| **松开手指 / 松开鼠标** | 在松手的位置**投放**（手机上的标准手感：按住找位置 → 松手放） |
| `空格` / `回车` / `↓` | 投放当前娃娃（键盘） |
| `←` `→` | 微调瞄准位置 |
| `P` | 暂停 / 继续 |
| `R` | 重开一局 |
| 左栏「难度」`−` `＋` | 调 1~10 级（本局不生效，下一局生效） |

> 手机端细节：**连点屏幕不会被当成「双击放大」**（`touch-action: manipulation`，只禁双击缩放、保留双指缩放）；
> 手指被系统手势或来电打断（pointercancel）时**不会误放**；两指乱按也只认第一根手指、只投一颗。
> 棋子被拖出棋盘外也没关系 —— 指针被 capture 住了，仍然跟手、松手照样投放。

**选图（挑你自己想要的 11 只）**

1. 点右上角 **🖼 选图** 打开小窗口（可拖动标题栏、可折叠）。
2. 左边是 **11 个位子**（按大小排好，带颜色条、角色名、⌀ 直径）；右边是**图片库**，按乐队分组。
3. **点一张图 → 点一个位子**放上去；也可以直接把图**拖**到位子上；**双击图片** = 放进第一个空位。
4. 位子右边的 **✕** 清空该位（回到图库默认）；顶部 **恢复默认** 一键全部复原。
5. 没选满 11 位就关窗口，会提示还差哪几个尺寸的位子。
6. 你的选择存在本机（`suika.pick.v1`），换图不影响图库本身。

**排行榜**

1. 右栏填名字（默认「玩家」）→ 本局结束后在结算画面确认名字 → 点「确认并上榜」。
2. 上方页签切换「实时 · 最近 20 次」和「总榜 · 前 100」；点「同步」手动拉取。
3. 自己刚提交的那条先显示「待确认」，写完再读一次确认真的上了远端才算成功。

**打赏**

结算画面点 **🍮 请作者吃小布丁** → 弹出收款码。

## 五、输入输出示例

### 5.1 输入：玩家操作

```
输入：鼠标移到 x≈240（棋盘中线），按空格
→ 输出：一颗「山吹沙绫」（⌀40）从投放线落下；投放次数 +1；进入 350ms 冷却

输入：两颗山吹沙绫碰撞
→ 输出：合成 1 只「上原绯玛丽」（⌀48），分数 +1；若 1 秒内再合成，出现连击条「连击 ×2  倍率 ×1.3」

输入：娃娃堆越过危险线并静止 2 秒
→ 输出：弹出「本局结束」结算卡：分数、最大娃娃、合成次数、最高连击、用时、难度、投放次数
        + 「上榜名字 [玩家] [确认并上榜]」+ 按钮【再来一局】【留在榜上看看】【🍮 请作者吃小布丁】
```

### 5.2 输入：URL 参数（都可叠加，线上/本地都生效）

| 参数 | 作用 |
| --- | --- |
| `?demo=1` | 自动开局并摆好场景（用内存存储，**不动你的存档**） |
| `&panel=1` | 直接打开选图小窗口 |
| `&over=1` | 直接演示「本局结束 → 结算画面」 |
| `&diff=8` | 直接把难度设成第 8 级（走和界面按钮同一条代码路径） |
| `&pump=200` | 同步跑 200 帧（自检/截图用；等图片预加载完才跑） |
| `&shapes=1` | 把真实碰撞体画出来（黄色圆组） |
| `&squash=0.28` | 把"正在被压"的形变状态摆出来 |
| `&donate=1` | 直接打开「请作者吃小布丁」弹窗 |
| `&close=1` | 配合 `panel=1`：试着关窗口，触发"没选满"提醒 |
| `&combo=6` | 把「连击」HUD 摆成 6 连（走真实的 HUD 更新路径；手机端用来确认分数面板不会被撑高） |
| `&board=textdb\|rest\|local` | 强制用哪种排行榜后端（线上/自建/本机） |
| `&lib=none` | 演示模式也不生成占位图库 |

示例：`https://vanilla-icewagtail.github.io/bangdream/?demo=1&shapes=1&pump=300`

字段：`n` 昵称(≤12 字) / `s` 分数 / `d` 难度等级 / `m` 最大娃娃等级 / `c` 最高连击 / `t` 提交时间。
**没有个人排行表**：同一玩家也只按每局入榜（有测试盯着）。
上限：总榜 100 条、实时榜 40 条（展示最近 20 条）。

### 5.5 输出：自建服务器 API（`server.cjs`）

```
GET  /api/health  → {"ok":true,"service":"suika-scores","count":2,"updatedAt":1730000000000}
GET  /api/scores  → {"ok":true,"count":2,"entries":[{...},{...}]}
POST /api/scores  ← 单条 {"n":"沙绫","s":386,"d":5,"m":9,"c":6}
                  ← 或批量 {"entries":[...]}（最多 50 条）
                  → {"ok":true,"accepted":1,"duplicated":0,"rejected":0,"rank":1,"count":3}
错误：坏 JSON → 400；超过 256KB → 413；同一 id 重复提交只记一次
```


```json

  "h": 384,
```

## 七、版本改动记录（含踩坑复盘）

### v0.4.7
- **音频加上限流器**（`js/config.js` 的 `createAudioLimiter`）：同时最多 8 个声部、
  任意两声至少 18ms、同一个音至少 45ms。连击连爆、危险线报警叠加时不再爆音/掉音。
  （不管以后用合成音还是真实音频文件，这道限流都要有 —— 手机混音声部本来就只有 8~16 个。）
- 合成音现在按 **tier 分别节流**（`merge3` / `merge11` 互不压制），并记录声部回收（`onended` 兜底定时器）。
- 切后台挂起 `AudioContext`、切回恢复：省电，也避免积压音效一起响。
- README 补「音频」小节：现在为什么是零文件方案、以及**要加真实音频文件时的数量/体积约束**
  （解码内存 ≈353KB/秒、并发 8~16、启动解码开销、GitHub 单文件 100MB 上限、格式要出两套、iOS 静音键）。
- 新增 2 项音频节流测试；全量 **100/100**。

### v0.4.6
- **手机端切后台不再清零**。切后台再回来「数据清零」多半不是逻辑 bug，而是系统为省内存把页面
  直接丢掉、回来时浏览器**重新加载**了一次（最高分/昵称在 localStorage 里，所以还在，只有这一局没了）。
  现在把「打到一半的这一局」也存进 `localStorage`：
  · **什么时候存**：切到后台（`visibilitychange`）、页面要卸载（`pagehide`）、暂停、以及玩的时候每 2 秒一次；
  · **什么时候清**：这一局结束（结算 / 重开）之后；
  · **什么时候恢复**：下次打开页面时，存档在 12 小时内且结构完好，就直接接着打（右上角提示「已恢复上一局：N 分」）。
  · 存档是纯数据（分数、统计、每只玩偶的位置姿态），一个快照几 KB；演示模式（`?demo=1`）不读不写。
- 切到后台时**自动暂停**（免得切走期间被判定失败），切回来若本来是我们暂停的会自动继续。
- 引擎新增 `snapshot()` / `restore()`；新增 2 项逻辑测试（快照往返、坏存档不炸）与 2 项页面测试
  （切后台自动存档 + 用同一份 localStorage 重新加载页面后接着打；停在开始界面/演示模式不写存档）。

### v0.4.4
- **触屏手感：改成「按住瞄准 → 松手投放」**。原来 `pointerdown` 里直接 `drop()`，手指一碰屏幕娃娃就掉，
  手机上根本来不及找位置。现在按下只瞄准、拖动跟手、**松手才投放**；
  用 `setPointerCapture` 保证手指划出棋盘也继续跟手、松手照样投放；
  `pointercancel`（系统手势/来电打断）不投放；两指乱按只认第一根、只投一颗。
- **手机连点不再被当成「双击放大」**：`html, body { touch-action: manipulation }`
  （只禁双击缩放、保留双指缩放，不牺牲无障碍）+ `-webkit-tap-highlight-color: transparent` 去掉点按灰块；
  棋盘本身更严格，仍是 `touch-action: none`，保证「按住拖动瞄准」时页面不跟着滚。
- 新增两个页面测试（走真实 pointer 事件 + 数引擎投放次数）与 CSS 断言，把上面两条钉住；全量 **94/94**。

### 更早的坑（原样保留，都是真踩过的）

1. **娃娃悬在半空不落**：根因是 Matter.js 的「沉睡」——速度接近 0 时被判睡着，引擎**不再加重力**。
   已关 `PHYSICS.enableSleeping`；同时把摩擦从 0.3 降到 0.1（静摩擦 0.6 → 0.16），
   墙壁保持 0.3（不然靠墙会滑）。验证：静置 30 秒果堆最大位移 0.05px。
2. **水果穿墙飞出去**：Matter 没有连续碰撞检测，8px 薄墙会被高速穿透 → 墙加厚到 90px（BULK）

3. **服务端并发丢成绩**：3 个人同时提交，「读→合并→写回」互相覆盖，最后只剩 1 条（真浏览器复现）。

5. **结算画面被吞**：`hideOverlay()` 里 180ms 的延迟隐藏定时器会把之后打开的遮罩又藏起来

## 九、已知限制 / 后续可以做的

**限制（说清楚比藏着好）**

- 第三方 KV 榜**没有服务端校验**，谁都能改那张榜（客户端凭据等于公开）→ 成绩只能当娱乐。
  想要防乱写就切到自建 `server.cjs`（`provider: 'rest'`）。
- 榜单数据存在第三方服务器上，昵称与分数会发过去（和访问任何网站一样，对方能看到 IP）。
- 自愈机制（本地缓存 ∪ 远端取优）意味着远端**没法被单方面清空** —— 想重置得换 `BOARD_SYNC.textdb.endpoint` 里的 key。
- 非圆形碰撞的代价：娃娃**不会滚**，堆得更稳但可能卡在缝里不下去。想对比，把 `js/engine.js` 里 `shapeOf` 传 `null` 就退回圆形碰撞。

**想继续做**

- 换位（当前 ⇄ 下一只）、撤销一步、每日最高分、按难度分榜。
- 更多娃娃 / 更多乐队（加图片后重跑 `tools/bangdream/build-library.cjs` 即可）。
- WebP 压缩素材（当前 PNG 合计 9.3MB，首次开选图窗口要下约 600KB 缩略图）。
- 反作弊：切到自建后端 + 服务端校验分数上限。
