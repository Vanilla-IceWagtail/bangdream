## 🧸 这个文件夹就是玩偶版（游戏名：合成邦高祖！！！）

> **单独的玩偶版，没有替换原版**（原版仍在 `..\合成大西瓜\`，线上站点也没动）。
> 打开：双击 `启动游戏.cmd`，或直接双击 `index.html`。

**素材**：桌面 `bangdream` 里的 45 张 BanG Dream! 毛绒玩偶 —— 9 支乐队 × 5 位角色，
**文件夹名 = 分组**，**文件名 = 角色名**，直接用在选图窗口里。

| 项目 | 做法 |
| --- | --- |
| 格式 | 45 张里 40 张扩展名是 `.PNG` 但**实际是 JPEG**（没有透明通道）→ 先转真 PNG 并降到 1024px（`tools/bangdream/convert.ps1`） |
| 抠图 | 纯白底泛洪抠掉（只删连通到边框的白，玩偶身上的白不会被吃掉）→ 裁到轮廓外接框 → 缩到 384px，另出 96px 缩略图 |
| **碰撞体积** | **按玩偶轮廓拟合一组圆**（每张 7~18 个，平均 12.9 个，覆盖率 87%~96%），游戏里用 Matter.js **复合刚体**（`Body.create({parts})`）—— 不再是"一个包住整只玩偶的大球" |
| **大小随水果** | 玩偶长边 = 该级水果直径（樱桃 ⌀40 → 西瓜 ⌀250），碰撞体按同一比例缩放：**看着多大，撞起来就多大** |
| 渲染 | 玩偶按整只尺寸画（不再裁成圆形），跟随刚体旋转；刚体位置是质心，渲染时按质心偏移回正 |
| 选图窗口 | 9 个乐队分组页签、点图 → 点水果位、颜色边框 = 水果 = 大小、没选满 11 张会提醒 |
| 调试 | `?shapes=1` 把真实碰撞体画出来（黄色圆组），肉眼核对碰撞形状 |

**物理手感的变化（重要）**：圆形水果会滚动、能自己滑进缝里；换成贴合轮廓的形状后，
玩偶**不会滚**，堆得更稳，但可能卡在缝里不下去 —— 这是"按真实轮廓碰撞"的必然代价。
想对比，把 `js/engine.js` 里 `shapeOf` 传 `null` 就退回圆形碰撞。

### 🍮 果冻手感（QQ 弹弹）

参考了 [BigNaiWa](https://yhsome.github.io/BigNaiWa) 的做法（读它源码得到的结论：它是自研 PBD 引擎，
果冻感拆成两层）。我们也拆成两层，**两层互不干扰，所以既弹又稳**：

| 层 | 做法 | 参数（`js/config.js` → `RULES.jelly`） |
| --- | --- | --- |
| **回弹（物理层）** | 弹性系数从 0.12 提到 0.42；关键补上了 Matter.js **没有**的东西：法向接近速度低于阈值时把这一对接触的弹性**清零**，所以堆子静止时不会一直微弹 | `restitution: 0.42`、`bounceThreshold: 0.92` px/步（≈55px/s，和 BigNaiWa 一致） |
| **挤压形变（渲染层）** | 刚体形状全程不变，只在画的时候沿撞击法线压扁、垂直方向拉长：`rotate(轴) → scale(1-k, 1+k×0.85) → rotate(-轴)`，然后指数衰减 | `squashMax: 0.30`、`k = 撞速/25`（满变形）、`squashDecay: 9`（τ≈111ms）、`stretch: 0.85` |
| **合成弹出** | 合成出来的新玩偶弹一下再缩回原大小 | `popScale: 0.28`、`popMs: 220` |

为什么形变放在渲染层：物理绝不会被形变带得自激抖动（这也是 BigNaiWa 最聪明的地方）。
`?shapes=1` 看真实碰撞体，`?demo=1&squash=0.28` 可以把"正在被压"的状态摆出来给截图看。

> 说明：BigNaiWa 的"果冻振动"是**观感**——形变其实是**单调指数回弹**（不是衰减振荡），
> 抖动感来自连续小碰撞反复顶起形变 + 真实多次弹跳。我们复刻的就是这个。
> 想要真的"抖/晃"（过冲再回摆）也不难：把 `sq` 的衰减换成二阶弹簧-阻尼
> （`sqV += (-k*sq - c*sqV) * dt; sq += sqV * dt`），大约五行。

**测试**：`node --test tests/*.test.mjs` → **82/82 通过**（含整页无头冒烟、3 个果冻回归测试）。

## 二、这次改的四件事

### ① 修掉「草莓粘住不落」的 bug

**根因有两个，都在物理引擎上：**

1. **Matter.js 的「沉睡」机制**（真正的元凶）：水果在半空互相卡住、速度接近 0 时会被判定为睡着，
   睡着之后引擎**不再给它加重力**，它就会永远挂在半空不再下落 —— 看起来就是「草莓粘在别的水果上掉不下来」。
   → 已关闭 `enableSleeping`（`js/config.js` 的 `PHYSICS.enableSleeping: false`）。
2. **摩擦系数偏大**：圆水果之间应该互相打滑滚开，原来的摩擦让它们像粘在一起。
   → 水果之间摩擦 `0.3 → 0.1`、静摩擦 `0.6 → 0.16`（墙壁保持 0.3，不然靠墙会滑）。

**量化验证**（`tests/logic.test.mjs`）：
- 半空放一颗草莓 → 一定会掉下去，不再停在空中；
- 30 颗水果乱丢后逐颗检查：**没有任何一颗水果悬空且不接触任何东西**；
- 静置 30 秒：果堆最大位移 **0.05px**、最大瞬时速度 0.037、平均速度 0 —— 既不下坠也不抖、也不自己滑动。
- 关掉沉睡后仍然完全不抖（迭代次数 12），所以这个改动不牺牲稳定性。

> 请重点试一下手感：现在水果更容易滚进缝隙、果堆更「松散自然」。如果觉得太滑，把 `PHYSICS.fruit.friction` 调到 0.15~0.2 即可。

### ② 连击加分

- **1 秒内连续合成**算连击；倍率 = `1 + (连击数-1) × 0.3`，**最高 ×2.5**（封顶约 6 连）。
- 加成取「倍率加成」和「每连击 +1 分」里更大的那个，所以小水果连击也有收益：
  - 连击 2 合成草莓（基础 1 分）→ **2 分**
  - 连击 2 合成西瓜（基础 55 分）→ **72 分**
  - 连击 6 及以上 → 固定按 ×2.5 算
- 表现：记分板下方出现**连击条**（连击数 + 当前倍率 + 剩余时间条），画布上会飘出金色的「连击 ×N」，
  粒子、屏幕震动和合成音的音高都会随连击提升；窗口超时后连击自动归零。
- 结算卡片新增「最高连击」。规则都在 `js/config.js` 的 `RULES.combo`。

### ③ 排行榜：全球共享（不需要自己的服务器）+ 两个榜

**在线地址：https://vanilla-icewagtail.github.io/merge-watermelon/** —— 任何人打开这个链接，
成绩都会进同一张榜，和你本机打开 `index.html` 看到的是同一张。

原理（`index.html` 是纯静态页面，自己没有后端）：**整张榜单就是一份 JSON 文档，存在第三方免费 KV 服务上**
（`js/config.js` 里的 `BOARD_SYNC.textdb.endpoint`），全世界玩家的浏览器读写同一份。

- **实时榜**：最近 20 次提交 —— 打开榜单面板就去拉最新（20 秒节流），所以看起来是实时的；
- **总榜**：历史前 100 —— 每 30 分钟自动刷新一次，也可以点「同步」手动拉；
- 自己刚打完那一局先以「**待确认**」显示，写完再读一次确认真的上了远端才算成功；
- **待上传队列**：提交失败就存本机，联网后自动补传，不丢成绩；
- **自愈**：每个客户端本地都缓存一份，读到远端时合并取优 —— 有人把榜刷没了、或者并发写丢了一次，
  任何一个还留着缓存的客户端下次读写就会把它修回来（代价：远端没法被单方面清空，想重置就换个 key）；
- **没有个人排行表**：文档里只有 `top` 和 `live` 两块，每局成绩只进榜，不给玩家攒个人历史（有测试盯着）。

想换成自建服务器（有服务端校验、能防乱写）：把 `js/config.js` 里的 `BOARD_SYNC.provider` 改成 `'rest'`，
用仓库里的 `server.cjs`（静态服务 + `/api/scores`）：局域网用 `启动共享榜.cmd`，
公网就把它丢到一台有公网地址的机器/容器上（只有 Node 内置模块依赖，`node server.cjs --port 8080`）。

**两个必须说清楚的风险（做法 C 的固有代价）**：

1. 第三方 KV **没有服务端校验**，谁都能改那张榜（客户端代码里的凭据等于公开），榜上成绩只能当娱乐；
2. 榜单数据存在别人的服务器上，你的昵称和分数会发过去（和访问任何网站一样，对方能看到 IP）。

（本机调试时可以用 `?board=local` 强制只记本机、`?board=rest` 走自建服务器。）

服务端接口（`server.cjs`，已带 CORS，方便以后放公网）：

```
GET  /api/health   → {ok, service, updatedAt, count}
GET  /api/scores   → {ok, updatedAt, count, entries:[...]}          # 前 100 名，按分数/等级/时间排序
POST /api/scores   → {ok, accepted, duplicated, rejected, rank, updatedAt, count, entries}
                      body 可以是单条成绩，也可以是 {entries:[...]}（最多 50 条）
                      id 重复只记一次；坏 JSON → 400；超过 256KB → 413
```

顺带修掉一个**并发丢成绩**的真 bug：3 个人同时提交时，服务端「读榜单→合并→写回」会互相覆盖，
最后只剩 1 条（真实浏览器里复现过）。现在整段读改写串行化，8 条并发提交一条不丢，
`tests/server.test.mjs` 里有回归测试盯着。

## 五、图片：内置图库 + 「选图小窗口」

图片**全部内嵌在游戏里**（`js/assets-builtin.js` 的 `SUIKA_IMAGE_LIBRARY`），游戏里**没有导入图片的功能**。
用户从图库里挑 11 张，分别放到 11 个水果位上：

1. 点右上角 **🖼 选图** 打开**选图小窗口**（可以拖动、可以折叠，方便一边看游戏一边挑）；
2. 窗口左边是 **11 个水果位**，每个位子带**颜色条**、水果名、直径（⌀）和当前用的图 —— **颜色 = 水果 = 大小**；
3. 窗口右边是**图片库**，**按分组**分类（分组页签「全部 / 圆润系 / 写实系 …」由图库里的 `groups` 决定）；
4. **点一张图 → 点一个水果位**即可放上去（也可以直接把图拖到水果位上；双击图片 = 放到第一个空位）；
5. 图**被分配到哪一级，边框就是那个水果的颜色**，图上还有一个徽章写着「🍉西瓜 ⌀250」—— 颜色、水果、大小一眼对上，
   不用再另开图例；
6. 顶部有 **恢复默认**：一键回到图库预设的默认图像；用户自己的选择存在本机（换图不影响图库本身）；
7. **没选满 11 个位子就关窗口**时，窗口里会弹一句提醒：还差哪几个水果位（例如「🥥椰子、🍈哈密瓜、🍉西瓜」），
   可以「继续选图」或者「就这样关掉」。图库是空的（还没内嵌图片）时不会弹这个提醒。

对用户（你）来说，要给我的是：

| 要给的东西 | 说明 |
| --- | --- |
| **图片文件** | 直接放到 `assets/fruits/`，或告诉我路径都行（不用自己导入、不用导出贴图包） |
| **分组说明** | 你打算怎么分组（比如「按画风」「按来源」「按用途」…），我按你说的填进图库的 `groups` |
| **默认图像** | 哪几张作为默认（开局就用它们铺满水果位） |
| **（可选）水果名单** | 现在 11 级是 樱桃/草莓/葡萄/橘子/猕猴桃/番茄/桃子/菠萝/椰子/哈密瓜/西瓜，要换我改 `js/config.js` |

我拿到之后会：压缩转 WebP → base64 内嵌进 `js/assets-builtin.js`（写好 `groups` / `defaults` / `builtAt` / `fingerprint`）
→ 重新打包单文件版 → 跑测试 → 压一个 commit（**不会**在你确认之前提交）。

图片建议：正方形最好（非正方形也行，会按圆形等比裁切）；透明底 PNG/WebP；边长 ≥ 水果直径的 2 倍
（樱桃 ⌀40 → ≥128px，西瓜 ⌀250 → ≥512px）；**图片内容尽量填满画布，别留大片透明边距**，否则水果在游戏里会显小。

> 还没有真图时，可以用 `?demo=1` 看窗口效果：会生成一个「3 个分组 / 22 张不同尺寸」的占位图库。
